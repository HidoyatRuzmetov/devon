# Account, department and file control/state evidence

This is a bounded overlay of the actual local journeys owned by the local-services audit.
`Verified` means a browser assertion reached the control and checked the real response or
persisted state; it does not mean every role × locale × viewport × failure combination passed.
The three engines are Chromium, Firefox and WebKit. Account coverage is aggregated across the
reports specified in `accounts-onboarding.md`; it is not one final 45-case report. All fixtures
are synthetic. The local API denies external transport before connection. No production data
or external Telegram, application-AI, email, or web-push delivery was exercised here.

Account/departments reusable sources: `account-boundary.qa.spec.ts`,
`departments-boundary.qa.spec.ts`; files: `files-boundary.qa.spec.ts`. Each suite has a separate
absolute output directory. No retries or skipped cases are used to obtain the stated passes.
Loading/read-error states are claimed only where the actual QA source asserts them, not simply
because a component renders a `StateView` in source.
