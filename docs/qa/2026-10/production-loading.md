# Genuine production frontend loading — 2026-10-09

The production performance gate is currently failing. Compiler success, successful collection and endpoint smoke checks do not satisfy the unchanged six-route LCP <2,500 ms, CLS <0.1 and score ≥90 budgets. Local measurements use actual production React web assets served by preview, real guarded API/database fixtures, simulated mobile 4G and CPU slowdown four. The API is development mode with the documented local ClamAV exception; these are not production API/HTTPS checks. External application AI, Telegram, SMTP, push and Sentinel calls remain blocked.

## Supported build and gate repair

The former build could emit development React because the repository's local environment declared development. `apps/web/scripts/build.mjs` now starts installed Vite with production selected before config/environment loading. An actual small React/Vite fixture fails before and passes after even with both inherited and file-based development settings.

The supported performance runner now always creates a fresh production web artifact before starting its disposable database. It forces `DEVON_E2E=0`, records all relevant frontend source inputs before/after with SHA256, refuses source movement, and validates source maps for the currently emitted assets. Stale production maps cannot satisfy a development/current-missing-map artifact; historical maps not matching current assets are ignored. The generated Rolldown runtime is the only existing explicit no-map exception. Production build settings do not mutate the caller's environment or change ordinary browser flows. Six routes and all original budgets are mandatory; no opt-in or collector-only success path remains.

Current build/package/performance contracts passed 15/15. This includes real Button-only and Calendar consumer builds and the actual configured HTML/public input hash, plus guarded alternative HTML/public path coverage. The audited UI package retains CSS and required test setup side effects; contracts have no public top-level registration effects. The Button-only before regression was unused personal schemas, not a missing calendar regression. Both current CSS preservation and real Calendar code retention are asserted.
